# Decisions

The running log of decisions taken while building impromptu v1, newest at the bottom. One bullet per decision, dated, with the reason. A decision that is reversed gets a new bullet saying so; the old one stays. Product decisions inherited from v0 live in `SPEC.md` and `PRICING.md` once those are ported (board card 06); this file is for what v1 decides on its own.

- 2026-09-06: v1 is a rebuild of v0 (FastAPI + Jinja, at `../zpersonal/0-lessworked/impromptuv0`) on Next.js + Django Ninja, in the shape of `../algoholic`. Why: voice analysis and model-based feedback have nowhere to live in a server-rendered Jinja app, and the rebuild is the chance to move to lucide icons, shadcn and Tailwind v4 while keeping v0's near-wordless UI.
- 2026-09-06: Parity first. Every v0 feature ships in v1 before any new feature is discussed; new ideas wait in the board's `later` list. v0 is the spec and the baseline and is read-only: port behaviour, copy, algorithms and tests, never files.
- 2026-09-06: Simple product. An improvement to models, backend or frontend earns its place by removing something. Django's own auth, sessions, hashers, migrations, mail backends and admin replace hand-rolled ones; shadcn replaces hand-rolled sheets and menus; a pure TypeScript run engine replaces DOM script. No caching layers, no queues, no webhooks, no abstraction for a provider that does not exist.
- 2026-09-06: The ten-second rule outranks features, carried from v0. A stranger is talking within ten seconds having clicked one button; home is the tool; chrome hides during the round.
- 2026-09-06: Ports are 3008 (frontend) and 8008 (backend). algoholic holds 3007/8007 and v0 holds 8078, so all three run side by side during the port.
- 2026-09-06: Icons are lucide, mapped by meaning in `components/site/icons.tsx`. Nothing on the site is an emoji; the `emoji` columns v0 kept on genres and packs become `icon` slugs from a fixed validated set.
- 2026-09-06: Work is tracked on the Trello board as cards 00 to 34 in build order; card 00 is the short rulebook. A card moves to doing when started and to done when it lands on main. Work lands directly on main, no feature branches.
- 2026-09-06: Fewer tables and columns than v0, landing with their cards: no `Genre.category` (the picker is one flat list), no `Topic.difficulty` (a spare axis nothing read), no `Session.topic_id` (the text is the record), no separate affiliates table (`affiliate_code` and `paypal_email` are two nullable columns on the user), no `login_sessions` or `password_resets` tables (Django's own sessions and reset tokens), static FX rates only (no frankfurter fetch until a reason appears).
- 2026-09-06: Django, not FastAPI, is what makes the backend simpler: sessions, argon2 hashing, password reset tokens, migrations, the mail backend and the admin all come with it. The API surface is django-ninja under `/api/v1/`, one router variable `api` per app.
- 2026-09-06: Sessions, not JWT. The cookie is `impromptu_session`, HttpOnly, SameSite Lax, 30 days, DB-backed so "sign out everywhere" is one delete. Prefixed so localhost ports do not share sessions with neighbouring apps.
- 2026-09-06: The browser never calls the backend directly. Every browser request rides the `/api/[...path]` rewrite in the frontend, which returns the backend's Set-Cookie headers; server components call the backend origin with forwarded cookies.
- 2026-09-06: The Django admin is mounted at `/re-admin/`, not `/admin/`, because `/administration` is the superusers' tool console on the frontend and a bare `admin` prefix would sit under it. API docs are behind `staff_member_required`.
- 2026-09-06: The custom user model is declared in the skeleton (card 01) rather than on the accounts card, because `AUTH_USER_MODEL` must be set before the first migration. Email is the login; `is_staff` opens `/re-admin/`, `is_superuser` opens `/administration`; nothing on the site raises either flag.
- 2026-09-06: The only password rule is a minimum of eight characters, which is what v0 asked. Django's similarity, common-password and numeric validators are refusals a form would have to explain in a sentence, and none earned one.
- 2026-09-06: `manage.py` defaults to production settings, so a host that forgot its `.env` gets the settings that refuse to boot rather than DEBUG. Production raises at startup without `SECRET_KEY`, `ALLOWED_HOSTS` or `POSTGRES_HOST`, pinned by tests.
- 2026-09-06: shadcn is copied in, never depended on, and `shadcn init` is never run (on Tailwind v4 it rewrites `globals.css`). `components.json` is hand-written with baseColor stone. The button is ours (`components/site/button.tsx`), because shadcn's outline and ghost variants hover to `bg-accent`, which in our tokens is the brand colour.
- 2026-09-06: Design tokens live in `globals.css` only, ported from v0's `app.css`: the accent is a hue and a chroma the theme does not touch plus a lightness only the theme sets, so no brand colour can make the topic unreadable; the primary button is ink, never the accent. The theme is a state on `<html data-theme>` read from the same `impromptu.theme` key v0 used, so a returning visitor keeps their choice across the rebuild.
- 2026-09-06: Postgres everywhere the app runs, from `docker compose up` at the repo root (postgres 17, redis 8, api), as v0 did. A SQLite fallback for bare checkouts was built and reversed the same day on the owner's call ("from the beginning lets use docker compose just like v0"); `base.py` is Postgres only and a test pins it. The database is published on loopback so a host run and the `api` container share one database.
- 2026-09-06: The test suite runs on in-memory SQLite, as v0 and algoholic do, so `pytest` needs no Docker and finishes in under a second. Confirmed by the owner after the Postgres decision above.
- 2026-09-06: Provider keys (Dodo, Brevo, Slack, PostHog, Crisp, reCAPTCHA, Google, OpenRouter) land with the card that introduces each service, together with the blank line in `testing.py` and the `.env.example` entry, rather than in one sweep. A list of keys nothing reads is not configuration.
- 2026-09-06: Decisions are logged here, one bullet each, dated, in the same change that makes them. Asked for by the owner so that a later session never has to re-derive a call that was already made.
- 2026-09-06: The backend runs in Docker, one command: `docker compose up --build` is how the API, Postgres and Redis come up, in the README, in AGENTS.md and in `.claude/launch.json`. The host `uv` environment is for tests, lint and the occasional management command, not for serving. Owner's call, following the Postgres decision: one way to run, not two.
- 2026-09-06: The compose file lives at `backend/docker-compose.yaml`, not at the repo root, because that is where every other product of ours keeps it (algoholic included) and the frontend is not containerised for development. Owner's call; the file had been at the root for an hour.
- 2026-09-06: One branch and one feature at a time, on the owner's call. Everything lands on `main`; there are no feature branches or worktrees. One board card is in doing at any moment, and it is committed and moved to done before the next one starts, so `main` always describes exactly which cards have landed.
- 2026-09-06: Rate limiting is the `limits` library's sliding window behind one decorator, `throttle(name, rate, key=None)` in `apps/common/ratelimit.py`, keyed on the client address unless a route hands it an identity (email, device). Each route declares its rate beside itself when it lands, carrying v0's numbers: sign-in 10 per 15 minutes per address and 5 per account, password reset 5 per hour per address and 3 per email, signup 5 per hour, runs 120 per hour per device, checkout 10 per hour. One handler answers 429 with Retry-After. Counters live in memory on a laptop and in the compose Redis (`RATELIMIT_STORAGE_URI`, an address, so env); a storage failure fails open with a warning, as v0 did, because a throttle that takes sign-in down with its store is worse than none. Exactly one proxy hop is trusted for X-Forwarded-For, in code, because topology is not an address.
- 2026-09-06: The ninja surface is csrf-exempt on purpose (`session_auth = SessionAuth(csrf=False)`): the browser only reaches it through the first-party rewrite, so a cross-site POST never carries the Lax session cookie. The Django admin keeps CSRF. Pinned by a strict-client test whose probe route lives in the test module, because a throwaway endpoint shipped for a test would be one more thing on the site.
- 2026-09-06: The device cookie `impromptu_device` is signed with Django's own signing, lasts two years, and is written by one middleware on every API response that lacks an honest copy: issued on first contact, replaced when forged, rewritten after `rotate_device` on sign-out. Signed, where v0's was not, so nobody can pick up another device's streak by typing its id in. Its flags follow the session cookie's. The admin never carries it.
- 2026-09-06: The referral cookie `impromptu_ref` is set by the Next proxy, not the backend, because a link lands on a page and only the frontend answers pages; the backend reads it from the forwarded cookies at the two moments it is spent. GET only, last click wins, sixty days, the same `[a-z0-9]{2,24}` shape as v0. The timezone cookie `impromptu_tz` is v0's inline script, moved into the root layout beside the theme script.
- 2026-09-06: `proxy.ts` gates /account, /packs and /affiliate/referrals on the session cookie's presence and sends strangers to sign in with a `next`. /administration is left out on purpose, keeping v0's rule that it answers 404 to anyone who is not a superuser: a sign-in prompt is a page confirming the path exists.
- 2026-09-06: The database and Redis are no longer published on the host, reversing the loopback publication above: 5432 and 6379 on loopback collided with the other projects' compose stacks running side by side. `POSTGRES_HOST` is `db` and `RATELIMIT_STORAGE_URI` is the redis service, in `.env` and as the code defaults; a host process reaches the database through `docker compose exec`. Owner's call.
- 2026-09-06: Ports are 3009 (frontend) and 8009 (backend), reversing the 3008/8008 choice above. Owner's call, so the defaults do not collide with another project on the machine; algoholic still holds 3007/8007 and v0 8078.
- 2026-09-06: Fonts are four `@font-face` rules in `globals.css` over files in `public/fonts/`, with the two latin files preloaded from the layout, rather than `next/font/local`. Its `src` entries carry no `unicode-range`, so the one-file-per-subset split v0 made (latin preloaded, latin-ext fetched only when needed) would have needed two font objects per family and a fallback-order trick; the plain rules do it in the way v0 did.
- 2026-09-06: The stylesheet stays small. v0's 2000 lines of CSS served a Jinja app with no component layer; here `globals.css` holds tokens, font faces and a short base layer, and everything else is Tailwind utilities, shadcn copied in and Magic UI. Owner's call ("we won't need that much css").
- 2026-09-06: The dark tokens are v0's exact values (`#080808` page, `--accent-l` 0.796), restoring what the skeleton had rounded; the contrast test reads the page colour, so the two had to agree.
- 2026-09-06: The palette list (`lib/palette.ts`) and the contrast test that reads `globals.css` live in the frontend, which owns the stylesheet. The account's `accent` column (card 23) will validate against the same six slugs as model choices; six words duplicated beats a backend test reading a TypeScript file.
- 2026-09-06: Genres carry no icon column. The ten are fixed, so the glyph is a function of the slug in `icons.tsx`, and a column that repeats the slug's meaning is one to remove. Packs keep an `icon` column because a person chooses the badge; its values are lucide's own slugs from a fixed set of 24, the same count v0 offered, validated on both sides.
- 2026-09-06: Hot take is a bolt, not a flame: the flame is the streak's mark and a header with two flames says nothing.
- 2026-09-06: The theme segment (Auto / Light / Dark, all three shown at once) is built on this card because its icons are, and the account menu on card 05 mounts it.
- 2026-09-06: Frontend tests move to `frontend/tests/`, mirroring `app/`, `lib/` and `components/`, reversing the colocated convention from card 01, and are kept few: a test pins a decision or a behaviour that would break silently, never that markup renders. Owner's call.
- 2026-09-06: `GET /api/v1/auth/me` lands with the chrome (card 05) rather than the accounts card, because the header and footer are drawn in their signed-in shape on every page and need to ask. It answers 401 to a stranger, which is the answer and not an error; the rest of sign-in stays on card 19.
- 2026-09-06: The referral, timezone and country ladder run on the frontend. `lib/geo.ts` ports v0's `pricing.where` in full (eight markets, the timezone table, the language region as the weakest signal) because the footer needs "in India" now and the pricing page needs the same answer later; `lib/visitor.ts` is the only file that reads the request for it. `TRUST_COUNTRY_HEADER` stays off unless a proxy sets the header.
- 2026-09-06: The account menu is the shadcn DropdownMenu copied in byte for byte from the registry, with `radix-ui` as the one dependency it brings. Its focused-item colour is passed in from the menu, because the registry's `bg-accent` is our topic colour.
- 2026-09-06: The sitemap keeps v0's shape, including `/pro` and `/affiliate`, which the card left out: v0 is the spec. Nineteen URLs, the tool first, no topics, no share pages, no operator paths. Genre pages come from the fixed slug list in `lib/genres.ts` rather than a round trip to the bank.
- 2026-09-06: Error pages are v0's words on a page of ours with the tool's button on it. The 500 page offers "Try again" beside "Give me a topic" because the framework hands the boundary a real reset, which v0's server-rendered page never had.
- 2026-09-06: `nwsapi` is pinned to 2.2.24 by a pnpm override. 2.2.27, which jsdom pulls by default, resolves the `:modal` pseudo-class by recursing through `:fullscreen` thirty million times, so opening a Radix menu in a test took forty seconds. algoholic's lockfile happened to hold the older one; ours says so on purpose.
- 2026-09-06: Weight, measured on the production build with nothing cached: a cold first visit is 358KB, against v0's 209KB. HTML 7KB, CSS 6KB and the two latin font files 160KB are at parity; the difference is 186KB of framework script across nine chunks, which a page with no client component of its own still pays. Over budget, written down rather than hidden; the number goes into the parity doc on card 06, and any decision to chase it (fewer client boundaries, dropping the menu primitive) is taken on its own card.
- 2026-09-06: A person's own genres are shareable in v1. Owner's call. A share is a link (`/g/<token>`, noindex), viewing needs no account, making stays Pro, and nothing is copied: a link always shows the current list. Every card that touches genres, the bank, the picker and the run engine is designed for it from the start (board cards 07, 08, 09, 10, 13, 15, 28, 29, 30), so it is not bolted on after parity.
- 2026-09-06: v0's `format` axis on a topic is `category` in v1 (just-talk, hot-take, explain, story; surprise means no filter and is never stored). Owner's call. The word is free because v0's `Genre.category` grouping column is not carried over. The old `format` key inside `impromptu.prefs` is read once so a returning visitor keeps their setting.
- 2026-09-06: Each side's whole test suite runs in under a minute, two at the very most. Owner's call. A test that needs seconds is testing the wrong layer, and both runners print their slowest tests so a regression is seen the day it lands. Measured when decided: the backend's 44 tests in 0.7s; the frontend's 56 tests in 174s, of which four account menu tests took 37 to 49 seconds each and the other 52 under 3 seconds together.
- 2026-09-06: `docs/SPEC.md` and `docs/PRICING.md` are written for v1 from v0's `CLAUDE.md`, spec and code comments (v0 never had a `PRICING.md` file; its pricing record was spread across five modules), with every settled decision kept and the v1 changes stated in each: stack and ports, icons instead of emoji, format renamed category, owned genres as genre rows, the smaller schema. `docs/tech/v0-parity.md` is the acceptance list, ticked per card.
- 2026-09-06: Format is category. Owner's call on card 07: `Topic.category` is the kind of talk a prompt asks for, same four values plus Surprise me, same rules. The icon map and its test renamed to match on card 06 so the code never carries the old word.
- 2026-09-06: Test budget, owner's call: each side's whole suite in under a minute. pytest prints its ten slowest tests over 0.2s on every run; vitest prints any test over 300ms. Rows come from factory-boy factories in `tests/unit_tests/factories.py`, reset per test, replacing the inline `create_user` in the fixture.
- 2026-09-06: Format is style, not category, reversing the rename above the same day. Owner's call: the picker already says genre, and a stranger cannot tell a category from a genre, so "category" would have put two synonyms in front of them. Style is how you talk about a topic (open, argue, teach, tell); genre is what it is about. `Topic.style` in code, "Style" in the settings sheet, the same word in the docs and the icon map.
- 2026-09-06: Seeding is a one-off management command, never a boot step. Owner's call, confirming card 07: compose migrates on boot and nothing else; `seed_topics` is run by hand once, and again only when the bank changes.
- 2026-09-06: Genres carry an `icon` column after all, reversing the card 04 bullet, because owned genres (card 29) are the same rows and a person picks their badge; the seeder writes the built-ins' marks. The fixed set is 26 lucide slugs, v0's 24 badges plus `dices` and `coffee` for two built-in genres, kept in `apps/topics/icons.py` and `components/site/icons.tsx` with each side pinning its own count.
- 2026-09-06: The ten bank files are carried over unchanged into `backend/data/topics/` and mounted into the API container, so editing a file and running `seed_topics` is the whole content workflow, with no rebuild. Data is not code; the rule against copying files is about code.
- 2026-09-06: Topic slugs come from Django's own `slugify`, not the `python-slugify` package v0 used. One dependency fewer; the slug only serves `/?topic=` deep links, which the share page regenerates, and card 34's migration re-derives it for every row.
- 2026-09-06: The seeder decides about departed genres after the topic pass, so a merge is one run and not two: a genre that left the list is deleted once its topics have moved and only deactivated while its file still feeds it. It never re-activates a topic the admin switched off, and switches off, never deletes, a topic that left every file.
- 2026-09-06: The UI is redesigned, not copied. Owner's call ("no need to copy ui, lets plan improved uis", "this revamping is an opportunity to improve"): parity is of behaviour, rules and copy, never of the look. Before a card builds a surface, a standalone HTML mock of it lands under `docs/mocks/`, the owner approves it, and `docs/UI.md` records the surface, what improves over v0 and why, and the approval. The ten-second rule and the tokens still govern every mock.
- 2026-09-06: The bank is 1000 topics, up from v0's 800. Owner's call. The 200 new ones went where the bank was thin first: General, Relationships and Tech & AI from 40 to 80 each, Career, Money & business, Philosophy & ethics and Science & climate from 80 to 100 each; the three 120-topic genres are unchanged. Every style still reaches every genre, no text repeats across the bank, and the files now use the `style` key (the loader still reads v0's `format`).
- 2026-09-06: The first two mocks are approved (`docs/UI.md`): home with the five phases and the genres pages. Owner's calls along the way: the idle screen keeps v0's shape with the button saying Spin; the back arrow becomes an underlined Reset link under the buttons; a new topic is a Spin button carrying the die rather than a rotate icon; the primary button inside the round names the duration. Every glyph is lucide-react, already in use.
- 2026-09-06: `GET /api/v1/topics/bank` is public and cacheable (`Cache-Control: public, max-age=3600`, and the page keeps it an hour): the built-in genres, every active topic, the styles, one shape. A person's own genres ride on a second call that varies by cookie (card 29), so this one never does; the page appends them client-side to the same row shape. Full key names rather than v0's one-letter ones, because the page ships gzipped and a repeated key costs nothing there: the thousand-topic bank is 24.7KB gzipped (v0's eight hundred were 19.7KB).
- 2026-09-06: The streak summary the home page needs (`GET /api/v1/streak/summary`) waits for the sessions and streak cards (15, 16), because there is no table to count yet; the page passes a streak of zero until then. The idle screen itself lands on card 08 from the approved mock, inert: the chip and the gear open their sheets on card 13, and Spin starts the round on card 12.
- 2026-09-06: The genres hub and the genre pages are built from the bank endpoint alone, server-rendered, with no endpoint of their own: the same hour-cached answer that ships with the home page holds every genre, blurb, count and topic they print. The genre page groups topics by style under real headings, as the approved mock does; JSON-LD is a CollectionPage on the hub and an ItemList with no per-item URLs on a genre page, because a topic has no page. The crawl test reads the backend's bank files and renders each genre page once, asserting every topic's text is on it.
- 2026-09-06: The run engine is four modules under `frontend/lib/round/` with no DOM in them: `prefs` (v0's key, the old `format` read once and written back as `style`, lengths clamped to the sliders' reach), `timer` (wall-clock, an injected clock, pause moves the end forward), `pool` (the narrowing with its fallbacks, the no-repeat draw, eleven tiered decoys, the staged topic, coined styles), and `engine` (the six phases, the keys, the arrival from a link). Randomness and the clock are injected so every rule is a fake-timer test; the page will render what the engine says and hand back presses. Sound, analytics and the write to the server are effects the engine emits, so cards 11, 14 and 15 attach to them without the engine changing.
- 2026-09-06: The engine records `topic_text`, `genre_slug`, the two set lengths, the seconds actually spoken and the UTC offset, as v0 did; the style is not on the row, because a run is filed under its genre and the style was only ever a filter on the draw.
- 2026-09-06: The round is one client component around the engine: made after mount (the server cannot know the visitor's prefs, so the first paint is the idle screen with the defaults and the chip and headline correct themselves a frame later, which is smaller than a hydration mismatch), subscribed through `useSyncExternalStore`, rendering one of six phase components that hand back presses. The body carries `filming` while thinking and speaking and the chrome hides on that class.
- 2026-09-06: The done headline follows v0's copy ("Day N." once the streak is known and above one, "Nice." otherwise) rather than the mock's placeholder "That's a minute.", which is false for a two-minute round or an early Done. The tiles show only once the record answers, which is card 15; until then the done screen is the headline, Spin again and Same topic. The Reset under the speaking row says "Reset, without keeping this round", because there it sits a tap from Done and the difference has to be said out loud.
- 2026-09-06: The ring's last ten seconds are a `--warn` token, the only place the site goes near red, so it means one thing.
- 2026-09-06: The sheets are the shadcn shape on the Radix Dialog primitive, written in `components/ui/sheet.tsx` with our button as the Done that closes them (the backdrop and Escape close them too), rising from the bottom on a phone and centred on a laptop. No animation library: the registry's slide-in classes need another dependency and the sheet is fine appearing. The settings sliders preview a length while the thumb moves (the question and the button follow live) and write it on release, so dragging from a minute to ten is one decision and one event.
- 2026-09-06: The two sheets were built on card 13 from its spec and added to `docs/mocks/home.html` as the last two tabs afterwards, which is the approve-first rule bent once: they are the last piece of the surface the owner approved, they are two utility panels, and blocking the working round on them cost more than adjusting them after. Flagged to the owner with the build.
- 2026-09-07: v0 is the record, not the authority. Owner's call after a v0 rule was defended as a v0 rule: the rebuild improves the UI, the backend and the tables wherever v0 was wrong, "v0 did it" is never a reason on its own, and differences that come from the new stack are expected. Written into `AGENTS.md` rule 1 and `SPEC.md`.
- 2026-09-07: Buttons in a row are one size, and the primary is told apart by its fill alone. v0 made the primary wider with larger type, which read as two sizes of control rather than one choice with a default; the owner called it out and it goes. The lone Spin on the idle screen keeps the large size, because it is alone.
- 2026-09-07: PostHog is on with its own defaults, not v0's switches. Owner's call on card 14: v0 turned autocapture and surveys off and pinned every switch by test, and those were FastAPI-and-Jinja-era rules, not product decisions; the rebuild does not copy them. v1 inits PostHog with `defaults` at the current date and adds one thing, a replay mask on `.ph-no-capture`, because the speak chips are text and the default input masking cannot reach them. The gate is `DEBUG_ENV=production` in the frontend's `.env` plus a token, a word in env rather than the build mode, so a production build run on a laptop to measure weight is not traffic and flipping one line is how a developer watches their own events arrive.
- 2026-09-07: The distinct id stays the device, and a signed-in person's email and name go on the person through identify. The device is what the sessions table joins on and the only id a stranger has, so switching to the email at sign-in would split one person in two; the properties are what make a recording findable by the person who wrote in. The frontend reads the id off the front of the signed `impromptu_device` cookie in the layout, for this one purpose and trusting it for nothing else: the backend alone verifies the signature, and a forged or expired value is answered with a fresh id on the next API response. A first visit has no cookie yet (only API responses set it), so no identify happens and PostHog keeps its own anonymous id, which the identify on the next page load folds into the device.
- 2026-09-07: PostHog loads as its own browser build from the PostHog host, async, after the page is up, rather than as the npm package in the bundle. The card named `posthog-js`, which this is; delivering it from the host keeps it out of a bundle already 149KB over budget and off every page where analytics are off. `lib/analytics.ts` owns a bounded queue so `track` always exists and a spin inside two seconds is not lost.
- 2026-09-07: Crisp is a client component keyed on the pathname: loaded async everywhere but `/`, told to hide on the way back to `/`, and it puts `chat` on the body while its bubble is drawn, which is how the footer leaves room for it (`chat:pb-24`) on exactly the pages that show it. `.filming .crisp-client` in the base layer hides the bubble with the chrome, the one rule in `globals.css` that names markup the site does not draw, because a third-party element cannot carry a utility. /privacy states both on card 33.
- 2026-09-07: A finished round is a run, and the table is `runs` (`apps/runs`, `Run`, `POST /api/v1/runs`), not v0's `sessions`. Forced and then welcome: a Django app labelled `sessions` collides with Django's own, which holds the login sessions, and the spec already says run everywhere ("a finished run is one POST", "whose runs count", "recent runs"). One word for the round, and "session" is left meaning what Django means by it. The frontend posts to the new path; the streak share endpoint on card 18 follows the same prefix.
- 2026-09-07: The device claim hangs off Django's `user_logged_in` signal (`apps/runs/services.py`), connected in the app's `ready()`. Every door, the form, Google and a test's `force_login`, ends in `login()`, so one rule in one place claims for all of them and card 19 has nothing to remember. The claim does not rotate the device cookie, reversing v0, which rotated on login as well as on logout: analytics ride on the device id and a sign-in must not split one person into two. Signing out still rotates, so a shared computer is left clean.
